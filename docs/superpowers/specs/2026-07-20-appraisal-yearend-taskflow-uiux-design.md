# 考核與年終「任務流重構」UI/UX 設計（2026-07-20）

## 1. 背景與問題定義

07-10 已完成一輪 IA 重整（`/appraisal-year-end` 巢狀路由 + 總覽工作台 + 15 條 UX 硬傷，已上 prod）。使用者實際使用後回報三種痛，經四路程式碼掃描證實其根源：

| 痛 | 根源（掃描證實） |
|---|---|
| 操作太繁瑣 | UI 直接映射後端端點：同一年終週期的設定/總表/明細是 3 個獨立頁面且無互跳；班級編制逐列儲存；手動調整一人一 dialog；考核建週期有 3 個入口且欄位不一致；「預覽分數」「同步分數」雙重預覽 |
| 看不懂太複雜 | 全模組無「現在該做什麼」引導；raw enum 直接顯示（`SUPERVISOR_SIGNED`、`PER_UNIT`）；同領域三種百分比寫法；13+ 金額欄無計算鏈說明；溯源抽屜只涵蓋 4 個扣款 key |
| 畫面太亂太擁擠 | 年終 grid 欄寬 ~1767px 必橫捲；26 欄分數預覽表；24 張規則卡平鋪無分組；工作台四卡等權重且卡序動態變動 |

另發現三個死路/誤導級問題（優先於美化）：

1. **簽核後無退路**：手改被後端 409 擋（僅 DRAFT 可改），但單筆退回端點不存在，畫面無出路提示。
2. **批次簽核失敗原因被丟棄**：後端回傳 `failed:[{settlement_id, reason}]`，前端只顯示計數。
3. **無權限按鈕照常顯示**（按下才 403）；過時寫死預設（學年 114、目標 160）。

## 2. 設計原則

- **後端狀態機與計算引擎不動**；只新增少量端點（§6）。UI 從「端點按鈕集合」重組為「任務引導流程」。
- 分 **3 批**交付，每批獨立走 worktree → staging 閘門 → 升 prod。
- 視覺語言沿用現有 admin token 體系與今日全站 PageHeader 慣例；不引入新設計系統。

## 3. 批次 1「止血與導引」

### 3.1 死路修復
- **BE 新增 `POST /year_end/settlements/{id}/reject`**（單筆退回草稿）：
  - 比照考核模組既有 reject 模式：原因必填、寫 audit、寫 settlement log。
  - 退回權限：`FINALIZED` 退回需 `YEAR_END_FINALIZE` 權限；`SUPERVISOR_SIGNED`/`ACCOUNTING_SIGNED` 退回需該關卡對應的簽核權限或核定權限。職責分離比照簽核規則：不可對本人的結算單操作；退回動作記錄操作者與原因。
  - 週期 `LOCKED`/`CLOSED` 一律不可退（維持 cycle_guard 語意）。
  - FE：明細頁與 grid 手改 409 錯誤訊息附「退回」動作入口。
- **批次簽核失敗明細透傳**（FE only）：批次結果改為可展開的失敗清單（姓名＋原因），不再只有計數。
- **權限前置**（FE only）：無權限的動作按鈕一律隱藏或 disabled＋tooltip 說明所需權限（例：新增年度週期需核定權限）。

### 3.2 誤導修復
- raw enum 全面中文化：`ListView` 的 `role_group`／員工 ID 改姓名、`RejectDialog` 的 status、規則編輯 dialog 的 rule_type 附白話說明。
- 寫死預設修正：建週期學年/學期依當前學期動態帶入；匯入日期依學年自動推算預設。
- `LOCKED` 語意明示：週期頭顯示「已鎖定：可簽核、不可再試算與修改」；非 OPEN 開總表顯示「未重算原因」提示。
- 年終 grid 主列與展開列金額位數統一（一律 `formatCurrency` 同一格式）。

### 3.3 工作台導引
- 頂部新增**「下一步」主卡**：依狀態推導唯一最重要行動＋一顆實心主色按鈕＋一句白話理由。推導優先序：例外阻斷級 > 年終待簽（OPEN 週期）> 考核待簽 > 可發放 > 建立缺失的週期 > 全部完成（顯示綠色完成態）。全模組僅此按鈕用實心主色。
- 四卡**固定順序**（考核→年終→例外→發放），移除動態換位邏輯；每卡補一行副標說明涵蓋範圍；「待簽核 N」與進度條關係補一句說明。
- 空狀態全部補行動連結；發放卡 0 筆顯示真空狀態（非「可發放 0 筆」）。

## 4. 批次 2「年終單一工作區」（本輪主體）

### 4.1 版面：左側流程導軌（使用者選定 B 案）
- 設定/總表/明細三路由合併為單一工作區 `/appraisal-year-end/year-end/cycles/:id`（舊三路徑 redirect 至對應步驟）。
- 左欄常駐垂直導軌：**設定 → 試算 → 調整 → 簽核 → 核定・鎖定**，每步顯示完成狀態與數字（例：簽核 12/23）；任一步可直接點擊切換；可收合（收合狀態記憶於 localStorage）。
- 右側內容區承載原三頁內容；工作區頂部為週期頭（學年、狀態、基準日、簽核進度條）。
- 顯式「開始試算」CTA 放在試算步驟（auto-build 副作用移除，改為明確動作；重新試算保留確認 dialog）。
- **BE 新增 `GET /year_end/cycles/{id}/progress`**：一支回傳導軌所需彙總（設定完成度、試算筆數/未匹配數、各狀態簽核統計、例外計數），取代前端拼 4 支請求。

### 4.2 grid 密度：摘要表＋欄位開關（使用者選定 B 案）
- 主表預設 6 欄：姓名／主結算／特別獎金合計／總額／狀態／操作，零橫捲；總額欄視覺加重。
- 表頭上方欄位開關 chips（考核上/下、紅利上/下、才藝、教課、超額、節慶差額、其他），勾選才顯示該欄；選擇記憶於 localStorage。
- 點列開**明細抽屜**：9 個獎金分項＋主結算組成；每項金額可展開「怎麼算的」（§4.3 溯源）。原 expand 展開列移除。
- 手動調整從「一人一 dialog」改為抽屜內就地編輯（顯示目前值，非空白盲改；「留空＝不覆寫」語意改為明確的「還原為自動值」動作）。

### 4.3 溯源擴充（BE）
- provenance provider 擴充正向獎金 key（考核上/下、紅利上/下、才藝鼓勵、教課獎勵、超額）；維持「Σ 逐筆 == 值」不變式；沿用既有 ProvenanceDrawer 呈現。

### 4.4 其他
- 清單頁補「進度」欄（迷你進度條＋下一步文字），OPEN 週期一眼可見卡在哪。
- 「考核年終發放」補頂層導覽入口（權限守衛沿用現有 payout 權限規則）。
- **BE 班級編制批次儲存端點**：設定步驟提供「全部儲存」；逐列儲存保留。
- **BE 例外中心 `deep_link` 改指新路徑**（現指 legacy 路徑靠 redirect 存活）；例外「前往處理」改新分頁開啟或處理後提供「返回例外中心」動線。

## 5. 批次 3「考核流程＋規則設定」

### 5.1 考核流程
- 當期總覽頂部加**橫向流程引導條**（輕量 checklist，非強制精靈）：建週期→加人→手填事件→同步分數→重算→簽核；每步顯示完成狀態、點擊直達（跨頁自動跳轉）。與年終導軌同視覺語言；考核頁面結構不合併（降低風險）。
- **合併雙重預覽**：「預覽分數」「同步分數」合併為單一 dialog——一次 dry-run，底部「確認寫入」（有寫權限才顯示）。
- **建週期入口統一**：三入口收斂到同一 dialog；學年/學期自動帶當前值；招生目標預設帶班級編制推導建議值（可改；維持業主「手動設定」裁定，建議值僅供參考）。建立後落在引導條下一步。
- 26 欄分數預覽表：預設只顯示「有異動的欄位」＋欄位開關 chips（同 grid 模式）。
- 13 欄手填表：加欄位凍結（員工欄）與分組表頭；保留既有鍵盤導航與「沿用上一週期」。

### 5.2 規則設定
- 24 張規則卡依性質**分組**（考勤／招生／才藝／懲處／加分）。
- **百分比統一**：UI 一律 0–100%，前端在 API 邊界換算 0–1（後端契約與儲存格式不動）。涵蓋：紅利門檻、逐年級門檻、舊生率。
- 規則編輯 dialog：rule_type 附白話說明＋範例；`input_field`（informational）自動帶入並隱藏。
- 規則歷史抽屜改用既有 `summarizeRule` 人話摘要（raw JSON 收入「進階」折疊）；`fmtRuleSummary` 與 `summarizeRule` 收斂為單一來源。
- **危險操作防護一致化**：獎金率新版本／目錄停用／目標修改統一「確認＋原因」；年終規則 ≥10 字強制原因改**常用原因快選模板**一鍵帶入（audit 保留、必填維持）。
- **影響提示**：規則儲存成功後若存在 OPEN 週期，提示「此變更於下次試算/重算生效 → [前往重算]」；設定頁頂部顯示目前 OPEN 週期連結。
- 三處目標人數（考核週期目標／年終 org_settings／實際值）在 UI 互相標註對照與連結；**資料模型整併不在本案範圍**。
- 不可寫的 tab 顯示「唯讀（需 XX 權限）」徽章。

## 6. 後端 API 變更總表

| 批次 | 端點 | 性質 |
|---|---|---|
| 1 | `POST /year_end/settlements/{id}/reject` | 新增；狀態機退回轉換＋SoD＋audit |
| 2 | `GET /year_end/cycles/{id}/progress` | 新增；唯讀彙總 |
| 2 | 班級編制批次儲存 | 新增；批次版既有逐列邏輯 |
| 2 | provenance 正向獎金 key 擴充 | 擴充既有 provider |
| 2 | 例外 `deep_link` 路徑更新 | 修正字串產生 |

不動：簽核/finalize/lock/archive 狀態機、year_end 計算引擎、salary engine、資料模型。每支新端點跟隨 OpenAPI codegen 同步（`dump_openapi.py` → `gen:api` → `gen:api:check`）。

## 7. 測試與驗證

- 每批 TDD 先行。BE pytest：reject 狀態機×SoD×audit、批次儲存、progress 彙總、provenance「Σ 逐筆==值」不變式。FE Vitest：下一步主卡推導優先序、權限渲染（隱藏/disabled）、0–1↔% 邊界換算、欄位開關記憶、批次失敗明細渲染。
- 金流相關（provenance 擴充、reject）過 finance-correctness-reviewer 終審。
- 每批收束前：FE 三棵測試樹＋typecheck、BE 全套 pytest、cross-repo parity 四向、openapi drift 檢查。
- staging 實機驗證清單隨各批實作計畫列出；e2e 照例不碰 `/calculate`。

## 8. 非目標（明確排除）

- 不動年終/考核計算引擎與任何金額公式。
- 不整併三處目標人數的資料模型（另案）。
- 不重排側欄或模組外導覽（今日 admin 稽核已處理的全站項不重做）。
- 考核頁面結構不做年終式的單一工作區合併（僅加引導條）。
- 手填表 13 欄不改資料結構（僅凍結欄＋分組表頭）。
